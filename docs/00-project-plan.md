## 1. 产品目标

将分散的问卷、访谈、应用商店评论、客服记录或群聊反馈，转化为可回溯的主题洞察、PRD 草稿和用户故事卡，减少手工归类与文档整理成本。

产品不承诺替代 PM 决策，也不负责自动采集、团队协作、账号权限或真实市场验证。

## 2. 当前用户流程

```text
导入 CSV/XLSX/TXT/粘贴文本
  → 清洗去空、去重、截断、脱敏
  → embedding + 聚类 + 主题洞察
  → 选择主题生成 PRD 草稿
  → 人工编辑、还原、审核和记录事件
  → 导出 PRD / 洞察 JSON / 主题 CSV
  → 生成用户故事卡并查看本地处理历史
```

每个主题保留反馈数量、代表原文和成员索引；任务卡保留来源主题、反馈数量和证据文本，避免结果脱离原始反馈。

## 3. 范围与交付状态

### Must — 已交付

- M1 数据导入：CSV/XLSX/TXT、粘贴文本、内置示例、列预览。
- M2 数据清洗：去空、去重、截断、手机号/邮箱脱敏和清洗统计。
- M3 聚类分析：远程或本地 embedding、UMAP（满足条件时）、HDBSCAN/KMeans 降级、噪声识别。
- M4 洞察：主题名、描述、情感、反馈数量、代表原文和成员回溯。
- M5 PRD 草稿：主题输入、结构化 Markdown、mock/live/auto LLM 模式。
- M6 人工审核：编辑、还原原稿、审核事件和采纳率统计。
- M7 导出：PRD Markdown、洞察 JSON、主题 CSV。

### Should — 已交付

- S1 响应式布局、暗色模式和主题/统计展示。
- S2 主题到用户故事卡的任务拆解：验收标准、优先级、来源证据和 Markdown 下载。
- S3 浏览器本地处理历史：最近 12 条会话、打开恢复和删除。
- 审核 JSONL 按大小自动归档，统计读取活动文件与归档文件。

### Could — 暂缓

- 词云或更丰富的高频词可视化。
- 多语言反馈自动翻译。
- 飞书/Jira 导出或集成。
- 跨批次反馈合并、需求去重与关联。

### Won't — 当前 MVP 明确不做

- 多账号和权限系统。
- 云端数据库和实时协作。
- 自动爬虫或自动采集。

## 4. 验收口径

### 工程验收

- 后端离线测试全部通过，当前为 83 个测试。
- 前端测试全部通过，当前为 37 个测试。
- 前端 TypeScript 检查和 Vite 生产构建通过。
- 浏览器 E2E 只有设置 `E2E=1` 时运行，覆盖导入、分析、PRD、任务卡和历史恢复主路径。
- Docker Compose 可启动：默认前端宿主端口 `5174`、后端宿主端口 `8003`；前端端口支持 `FRONTEND_PORT` 覆盖。

### 产品验收

- 合成演示数据可以完成导入、清洗、聚类、PRD、审核、任务卡和导出流程。
- PRD 和任务卡可以回溯到主题和代表原文。
- 无 LLM key 时可以使用 mock 模式演示，但 mock 结果不作为真实模型质量证据。
- 真人访谈、PM 盲评和问卷实验尚未完成，不能把自测结论写成真实用户验证。

## 5. 技术架构

```text
React/Vite SPA
  ├─ Import       输入、上传和数据预览
  ├─ Insights     清洗、聚类、主题洞察
  ├─ Review       PRD 审核、任务卡、会话保存
  ├─ Export       文件下载和审核统计
  └─ History      本地会话列表
        │ fetch / SSE
        ▼
FastAPI
  ├─ /api/pipeline/import
  ├─ /api/pipeline/clean
  ├─ /api/pipeline/cluster
  ├─ /api/pipeline/prd-gen
  ├─ /api/pipeline/task-cards
  └─ /api/review-log /api/health
        │
        ├─ embedding / clustering / insight services
        ├─ OpenAI 兼容 LLM Provider（live/mock/auto）
        └─ JSONL 审核日志；浏览器 localStorage 会话
```

当前没有应用数据库。`sqlmodel` 仍存在于依赖文件中，但不是现行存储实现，后续需决定移除或真正接入。

## 6. 关键决策

1. **降级优先**：外部 LLM 或 embedding 不可用时，系统仍能用本地模型、TF-IDF、哈希或 mock 完成可演示流程。
2. **人机边界清晰**：AI 负责归纳和草稿，人负责审核、优先级和最终产品决策。
3. **证据链优先**：主题、PRD 和任务卡都保留来源主题或原文证据。
4. **MVP 轻存储**：审核日志采用带锁和轮转的 JSONL，处理历史保存在浏览器，避免提前引入数据库和账号系统。
5. **合成数据诚实标注**：`data/demo/flowdesk_feedback.csv` 只用于演示和测试，不用于证明真实市场效果。

## 7. 后续开发顺序

1. 先完成真人访谈与 PM 盲评，更新 `docs/01-user-research.md` 和 `docs/03-metrics.md`。
2. 根据验证结果决定是否做词云、多语言和外部协作平台集成。
3. 在确认产品需要长期多用户使用后，再评估数据库、账号和跨批次数据模型。
4. 每次新增功能同步更新 `CONTEXT.md`、`TODO.md`、README、测试和迭代记录。
