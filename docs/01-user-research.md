# 01 · 用户调研

> 目标：验证 "PM 每周花数小时整理非结构化反馈" 的痛点，为 PRD 提供依据。
> 状态：**诚实降级已完成** —— 因求职冲刺期时间受限，未完成原计划的 3~5 位 1v1 访谈，采用「本人 PM/开发者双角度的场景复盘 + 竞品痛点交叉验证」代偿，并对局限如实说明。1v1 访谈列入 backlog。

## 为什么这样做（诚实说明）

作品集最重要的不是"形式上做过调研"，而是指标可追溯、局限不藏。当前产品与测试已能证明**痛点提出与方案匹配的逻辑自洽**；真人访谈数据是未来的加分项而非当前的项目前提。面试被问到时会主动坦承："1v1 用户访谈仍在计划，当前痛点定义来自我作为 PM 的实际工作复盘 + 对竞品缺口的分析。"

## 痛点假设（基于工作复盘 + 竞品分析交叉验证）

1. **归类去重耗时**：多渠道原始反馈（评论/问卷/群聊）语言杂、重复多，人工归类逐条读，是耗时主力。
2. **反馈 → 需求文档转化难**：从"用户语言"翻译到"产品需求"需要大量整理，且中间过程不留痕。
3. **难回溯**：整理后的结论找不到原始依据，评审/排期时当面对质拿不出原话。
4. **工具断层**：表格/问卷只负责收集，不做洞察；通用 AI 对话零门槛但无管线、不可复现。

（交叉验证来源：`docs/05-competitive-analysis.md` 对 Dovetail / 飞书多维表格+AI / 问卷星 / ChatGPT 粘贴 四类工具的缺口分析。）
